## Lát 1 · Migration & nền móng

**Không có mã F, nhưng chặn mọi thứ sau nó.** Hiện `synchronize: true` tự tạo bảng ở dev.
Làm migration lúc này khi repo mới có **1 bảng** thì rẻ; để tới M3 thì đã 15 bảng kèm dữ liệu.

Việc:

- [x] `data-source.ts` cho TypeORM CLI
- [x] Script `migration:generate` / `run` / `revert` / `show`
- [x] `bin/generate-migration.mjs` — tự cập nhật barrel sau mỗi lần sinh
- [x] Tắt `synchronize` ở mọi môi trường
- [x] Migration đầu tiên: `gift_posts` + tạo extension PostGIS
- [x] **Sửa CI**: job `integration` chạy `migration:run`; đã bỏ bước tạo extension thủ công
- [x] **Deploy**: production tự chạy migration lúc khởi động (`migrationsRun`)
- [x] Bảng `users` + `user_sessions` + migration
- [x] Contract trong `core-lib`: `IUser`, `IUserSession`, `UserRanks`, `UserStatuses`,
      `UserId`, và nhóm mã lỗi `0x03` (người dùng) + `0x04` (phiên)

**Xong khi:** `npm run migration:run` trên database rỗng dựng đủ bảng, và job `integration`
của CI xanh mà không cần `synchronize`.

## Lát 2 · auth-lib & F01–F04

`system/auth-lib`: JWT access + refresh rotation, `JwtAuthGuard`, `@CurrentUser()`, `@Public()`.

- [ ] F01 Đăng ký tối thiểu — username + password + xác nhận. Không cần email/SĐT
- [ ] F02 Đăng nhập đa định danh — username hoặc email/SĐT; kiểm ban; rate-limit khi sai nhiều
- [ ] F03 Refresh token — access ngắn hạn, refresh xoay vòng, thu hồi khi hết hạn
- [ ] F04 Đăng xuất — thu hồi session **và xoá FCM token của đúng thiết bị đó**

Băm mật khẩu dùng **bcrypt** đúng như cột công nghệ trong hợp đồng (argon2id mạnh hơn nhưng
lệch đặc tả — không tự đổi).

**Xong khi:** đăng ký → đăng nhập → gọi API cần quyền → refresh → đăng xuất chạy thông, và
smoke test phủ được chuỗi này.
